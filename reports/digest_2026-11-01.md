# Agent Eval Digest — 2026-11-01

## TL;DR
Sierra announced the Personal Agent Protocol at their summit, giving direct competitive signal on how a leading customer-agent company is standardizing agent-to-agent handoffs. Simantic launched firmware-level simulation for agents, which could improve deterministic testing of tool use and edge cases. Dayjob released a 50-task professional benchmark focused on real workflows, highlighting how narrow-domain evals expose gaps that generic benchmarks miss.

## 🎯 Top 3 para Connectly

### 1. [The Sierra blog - Corporate](https://sierra.ai/uk/blog/corporate)
**Por qué importa para Connectly:** Sierra's Personal Agent Protocol is a direct move by a top competitor into standardized multi-agent orchestration, which overlaps with our handoff logic and multi-turn goal completion on WhatsApp.
**Acción concreta:** Add a test case in Test Framework that simulates an external personal agent trying to take over or escalate a conversation and verify our agent follows the right protocol boundaries.

### 2. [Launch HN: Simantic (YC F26) – Firmware Simulation for AI Agents](https://news.ycombinator.com/item?id=50291116)
**Por qué importa para Connectly:** Simantic's hardware/firmware simulation approach could be adapted to create more reliable mock environments for our tool calls and multi-turn state, reducing flakiness in persona-driven tests.
**Acción concreta:** Prototype a small set of "firmware-style" mocks for common WhatsApp actions (order lookup, cart recovery) and measure how many false positives disappear from the current Test Framework suite.

### 3. [Dayjob: Tax – evaluating AI agents on 50 professional tax assignments](https://surgehq.ai/blog/dayjob-tax)
**Por qué importa para Connectly:** The benchmark shows that task-specific, multi-step professional evaluations surface tool-use and reasoning failures that text-only evals miss — directly relevant to testing order handling and FAQ resolution.
**Acción concreta:** Design a similar 20–30 task "Dayjob-style" suite for WhatsApp commerce scenarios (refund, address change, upsell) using our existing mock data and run it after every prompt change.
