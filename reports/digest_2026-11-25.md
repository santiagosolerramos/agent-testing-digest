# Agent Eval Digest — 2026-11-25

## TL;DR
Sierra released τ³-bench (knowledge evaluation) and a practical guide on building regression suites for agents that handle tools, escalation, and ambiguous inputs. Two WhatsApp-specific items surfaced on production guardrails and metrics. These are directly actionable for the Test Framework and our open questions on regression and persona-driven edge cases.

## 🎯 Top 3 para Connectly

### 1. 𝜏³-bench | Sierra
**Por qué importa para Connectly:** Sierra (direct competitor) just shipped an agent benchmark focused on knowledge handling in multi-turn scenarios, extending their prior τ-bench work.
**Acción concreta:** Download the benchmark and run our current personas against it to see where Test Framework evals diverge from Sierra’s coverage.

### 2. How to test and benchmark AI agents | Sierra
**Por qué importa para Connectly:** Explicitly recommends adding post-launch failure cases to a regression suite and testing tool use, policy boundaries, and escalation — exactly our open questions.
**Acción concreta:** Map Sierra’s test categories (ambiguity, missing data, tool conflicts) into our persona YAML and add a nightly regression job that replays them after prompt changes.

### 3. It's 11pm. A customer screenshots your WhatsApp bot promising a refund you never offered. What do you actually do next? | Ayush Gupta
**Por qué importa para Connectly:** Highlights the need for action audit logs, approval queues, and kill switches when running agents on WhatsApp at night.
**Acción concreta:** Add an “audit log + fail-closed” requirement to every new persona that triggers tool calls or refunds in the Test Framework.

### Regression Testing & CI/CD for Agents
### How to test and benchmark AI agents | Sierra
**URL:** https://sierra.ai/learn/how-to-test-ai-agents  
*Source: tavily | 2026-11-25*

Sierra’s guide walks through constructing regression suites that include tool-using flows, policy violations, ambiguous language, and inter-system data conflicts. It stresses continuously adding real production failures back into the suite. This maps almost 1:1 to the Test Framework’s current design and directly answers how to avoid drowning in false positives after prompt updates.
